# v0.2 Implementation Plan

> Agentic workers: implement inline with test-driven-development; use an independent reviewer before delivery.

**Goal:** repair Windows path correctness and remove redundant per-file metadata/identity work.
**Architecture:** native Windows path and enumeration helpers feed the existing transactional SQLite writer; cached database identity retains hardlink protection. Existing database schema remains unchanged.
**Tech Stack:** C++20, CMake, SQLite 3.53.4, Win32 file APIs.
**Spec:** docs/v0.2-spec.md.

## Constraints and review focus

- Preserve UTF-8 text, root overlap checks, reparse skipping, hardlink rejection and rollback.
- Handle extended input paths, >260-character descendants, root/UNC separators and missing database leaves.
- Fail on directory read/enumeration errors; observe identity changes before commit.
- Keep both MinGW and MSVC build paths and portable Linux core.
- Profile timings are diagnostic categories, not exact filesystem I/O percentages.

## Interfaces

- `EntryMetadata { path, directory, skipped, size, modified_at }` uses native paths and Unix seconds.
- `DirectoryCursor(directory).next(EntryMetadata&)` yields one entry at a time, throwing on enumeration errors.
- `IndexFileGuard(database, allow_single_link_fast_path).matches(path)` uses cached identity; `needs_checks()` gates per-file comparisons; `verify_unchanged()` runs before commit. Default is conservative; caller only enables the fast path for two confirmed local drive paths.
- `ScanResult.timings` reports milliseconds; `ScanResult.identity_checks` counts candidate file comparisons.

## Progress

v0.1 report committed and tagged as v0.1.0. Archived executable remains under ignored build/archive/v0.1 for measurements.

Debug and Release both passed 22/22 tests. New regressions cover volume-root trailing separators and local/UNC aliases of the same database; both failed before the fixes. An independent reviewer confirmed both fixes, valid UNC scanning with conservative identity comparisons, and no remaining P1/P2 findings. UNC administrative-share regression returns skip code 77 if the host does not expose that share; it ran and passed locally.

The first remote run passed Linux but MSVC exposed the Windows `max` macro in the CLI translation unit. Parenthesizing `std::max` in the path helper prevents macro expansion; remote build/test remains the cross-compiler regression check.

Benchmark and compatibility evidence: docs/v0.2-benchmark.md. The existing GitHub workflow runs MSVC on Windows and the portable Linux implementation on every push; its result is the gate for the release tag.
