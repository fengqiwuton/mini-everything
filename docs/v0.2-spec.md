# v0.2: reliable Windows scanning and profiling

User authorization: save the previous version in Git and implement/test the next version, following the review's path and performance priorities.

Keep C++20/CMake/SQLite schema version 1 and existing scan/search semantics. Support ordinary, relative, extended drive and UNC filesystem paths. Resolve Windows aliases using native path APIs; avoid the MinGW absolute/iterator bugs. Windows enumeration must index descendants beyond 260 characters or fail and roll back, never publish a silently truncated tree. Use native enumeration's attributes, size and write time. Skip reparse points.

Cache an open handle and identity for the index file. Only when both normalized paths are confirmed local drive paths and its initial hard-link count is one, avoid per-entry identity queries because the index's own path is excluded. For UNC, mapped network drives, other namespaces or multiple links, compare each file's identity with the cached index identity. Verify the link count again before commit and abort if it changed. Preserve rejection of existing database hardlinks and all-or-nothing replacement. Transient file-system changes are still not an atomic filesystem snapshot.

Expose scan timings (metadata/enumeration, file identity, SQL write including serialization, commit) and per-file identity query count via optional `scan --profile`. The portable implementation retains std::filesystem enumeration. Do not change default stdout summary/search TSV; clarify their distinct contracts in README.

Validate extended root/DB inputs, >260-character tree under an empty cwd, metadata timestamps, hardlinks, rollback, ordinary CLI, and schema compatibility. Compare archived v0.1 and v0.2 executables on the same controlled files, verifying equal indexed contents. Do not rescan D:/Users during development. Publish source and aggregate performance records, excluding actual user indexes and paths.
