# v0.3: 重扫缓存与可诊断性

用户在 v0.2 实测 693778 文件、75617 目录，耗时 108983 ms，其中 prepare 38726.11 ms。目标是定位并降低重扫数据库成本，保留 schema 1、搜索输出、严格错误回滚和多根目录行为。

## 已验证的原因与设计

在只读源数据库的 SQLite backup 副本上，使用项目同版本 SQLite 3.53.4，删除 769395 个节点：默认约 2 MiB 缓存耗时 38606.4 ms、溢出 347169 次；64 MiB 为 22122.3 ms、69323 次；128 MiB 为 17730.5 ms、41499 次。64 MiB 的删除加提交耗时仍低于默认，采用它作为通用默认值，允许用户调节。数据和文件名留在忽略的 build/ 下。

- `ScanOptions { int db_cache_mib{64}; }`，`scan(root, database, options = {})` 保持现有两参数源代码调用兼容。
- `scan --db-cache-mib N`：整数 1～1024，仅本次扫描连接使用；搜索保持原有只读行为。
- 缓存是 SQLite 页缓存的目标，按需分配，不是进程总内存的硬上限。保持 foreign_keys、trusted_schema、journal_mode、synchronous 和 cache_spill 策略。
- 保留 `prepare_ms` 聚合诊断；新增 open、transaction、schema、roots、clear、statements 子阶段。输出缓存命中、未命中、写出、溢出统计，包含提交。
- 扩展基准脚本，区分新建索引和重扫，逐条比较元数据及父路径；不同阶段分别计算中位数。
